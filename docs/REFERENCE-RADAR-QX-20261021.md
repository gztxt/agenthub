   它们**确实**是 cron 调度器且星数高于 `apscheduler`(7.6k) ⇒ 小库被挤出前五。
   这是「召回变大、分母也变大」的必然结果，不是扩展写错。

2. **mrr 下降**（0.367→0.157）：新命中的三条都在第 5 名，命中位置更靠后。
   重排能推前一部分（§5 实测：健康 0.5→1.0、全文检索 0→0.33~0.67），但**救不了 cron**
   （`apscheduler` #14 在重排窗口外）。**不要**再回头调打分权重（7 组已证无效，
   v2/v3 也只提高 mrr 不提高 hit）。
3. **词表是人工维护的**（`SYNONYMS`，27 条通用运维/检索词汇），只在这 5 个模块上验证过。
   换到产品名、领域黑话密集的模块时，扩展项会自然退化回「只有形态变体与分隔符归一」，

## 6. 重排层两个逻辑缺陷（2026-10-21 第二轮修复）

### 6.1 未判定被排到「已否决」之后（排序档位倒置）

`_judge_rank` 的原实现：`use/fork=0、read=1、skip=2、unjudged=3`，而函数自己的
注释写的是「未知必须排在已判 skip 之前」。**代码与注释相反**，且 `unjudged` 正是
「重排没看过的仓」——重排只覆盖词法前 8 名，第 9 名以后、以及模型只返回一部分条目时的
其余候选，全部带 `unjudged` ⇒ 卡面上**没看过的仓被压在被明确否决的仓下面**。

- 触发条件有两个，都很常见：① 池内 impl 候选 > 8；② 免费档只返回 4/8 条（实测）。
- 修复：`skip=3`、其余未知一律 `2`，档位恢复 `use/fork < read < 未判定 < skip`。
- 闸门：`TestJudgeRankLadder`（3 例）+ `TestPartialRerankOrdering`（真走 `apply_rerank`，
  断言 skip 沉底、unjudged 居中）。

### 6.2 免费档返回的是内容审核标签，不是 JSON

`openrouter/free` 会把重排 prompt 路由到内容审核模型，HTTP 200 但正文是：

```
User Safety: safe
User Safety: unsafe
Safety Categories: Malware, Needs Caution
```

4 轮实测命中 2 轮；换同池的兜底模型（`nemotron-3-super-120b:free`）**照样返回标签**
（`bad-json`）。这不是超时，**加超时救不回来**；也不是「模型不听话」，是路由选错了模型。

- 修复：识别 `^\s*User\s+Safety\s*:` 即记为 `safety-router` 并停止同池重试
  （免费档 2 个模型同池，再试只会再撞一次），省掉约 25s；付费档返回标签时**不**停止，
  仍走免费兜底（两者不同池）。
- 闸门：`TestSafetyRouter`（3 例，含「付费档命中标签仍要兜底」的反向用例）。

## 7. 匹配与重跑口径修复（2026-10-21 第三轮）

### 7.1 `matched < 2` 在单关键词下恒真，实现桶必空

覆盖度改成概念级后，过滤条件仍是常数 2。概念数由关键词决定：用户只填一个关键词
（或 LLM 抽词只回一条）时 `matched` 上限就是 1 ⇒ **过滤条件恒成立，全部实现桶候选被丢光**，
即使描述逐字命中关键词。

- 实测（假造检索返回，排除网络变量）：`keywords=["cron"]` 对
  `"a cron library for go"` 返回 `impl=0`、`status=lexical`；同样的候选在两个关键词下保留。
- 修复：门槛改为 `min(2, len(groups))`——有 2 个以上概念时行为完全不变（含现有 5 模块评测），
  只有 1 个概念时才不会自我否决。
- 闸门：`TestSingleKeyword.test_single_keyword_survives_filter`（真走 `collect`）。

### 7.2 模型输出大小写会丢掉判定

`rerank` 用 `item["repo"]` 与 `cands` 的 `full_name` 原样比对，判定标签也不归一：

- 模型把 `robfig/cron` 写成 `Robfig/Cron`（很常见）⇒ 该条判定被静默丢弃；
  若全部如此，整轮还被误判成 `degenerate`（实测 `out={}`、三个模型全 `degenerate`）。
- `judge` 写成 `USE` / `Skip` ⇒ `_judge_rank` 落到未知档（2），`skip` 不再沉底。

修复：仓库名按 `lower()` 建索引并回填规范名；`judge` 统一 `strip().lower()`，
`_judge_rank` 自身也做归一（双保险）。闸门：`TestRerankNormalization`。

### 7.3 「重跑」会把付费卡永久锁死在免费档

原 `api_refresh` 用 `meta["rerank_paid"]` 决定重跑是否付费。这个字段的语义是
**上一次真的用上了付费档**：付费失败回落免费后它是 `False` ⇒ 之后再点多少次「重跑」
都只走免费档，而免费池会被审核路由拦截（§6.2），用户无法恢复语义判定。

- 修复一：`meta["requested_paid"]` 记录**请求意图**；`refresh_body()` 取值顺序为
  「显式参数 > 上次请求意图 > 上次实际档位」，兼容旧卡。
- 修复二：`POST /cards/{id}/refresh?allow_paid=0|1` 显式指定；前端「重跑」按页面上方
  「允许付费重排」勾选传参（标题写明），不再隐式沿用。
- 修复三：`refresh_loop` 显式 `allow_paid=False` + `trigger="auto"`，并在卡面加一行
  「定时自动刷新（不付费）」。**自动任务不花钱**是硬约束；代价是自动刷新可能退回词法，
  卡上会写明原因，人工「重跑」可恢复。
- 闸门：`TestRefreshPaidIntent`（4 例，含「付费失败后意图仍在」与旧卡兼容）。

（较上轮 +6 例）。

## 8. 功能补齐（2026-10-21 第四轮）

三处都是「后端已具备、用户看不到/用不到」，不是新能力：

1. **代码标识符臂接入前端**。`POST /api/ref/scout` 一直收 `identifiers`（`/search/code?q="X" in:file`，
   命中给 `pre` 加 `0.25·min(1,hits/3)` 并能绕过 `cov<0.18` 过滤），但表单从不发送该字段 ⇒
   这条臂在生产里**永远为空**。线上实测（模块「终端 WebSocket 与端口转发」+ `node-pty`）：
   `code:node-pty` 臂返回 5 条，池 65，9 条检索臂全成功。
2. **切片不一致导致第三个标识符静默丢失**：payload 切 `[:3]`、`collect()` 只用 `[:2]`。
   已统一为 2（代码搜索限额 10 次/分），并经单测钉住 payload 与 collect 同源。
3. **卡面补「关键词来源」**：`keyword_source=fallback` 表示模型抽词失败、退回内置中文词典
   （覆盖有限、召回常整体跑偏），此前完全不可见 —— 用户只会以为「检索不准」。
   现卡面明写来源，`fallback` 时直接建议手填关键词重跑。

另修一处**过时断言**：代码注释与本文档曾写「免费档在审核路由上必失败」。
2026-10-21 线上两档实测：免费档 `openrouter/free` **成功返回 8/8 判定**（54.6s），
付费档 9.2s；且同条件 3 轮控制探针重排覆盖均为 8/8。故改为「**偶发**被审核路由劫持、
且慢约 6 倍，不可当默认」——`safety-router` 识别与停试逻辑保留（真撞上时省 ~25s）。

## 9. 边界声明

- 本报告 §2 的数字是词法口径，§5 是端到端（含重排），**两组数不可混用**。
- 结果绑定 2026-10-21 的 GitHub 语料；跨日对比前先重跑基线确认上游未变。
- 标注集仍是 v1（5 模块 / 13 仓），**扩到更多模块前，0.600 只能读作「这 5 个模块上的改进」**。
- 重排成功率本身不稳定（今日基线 3/5、4/5；qx1 5/5、5/5，同一代码路径、同一模型），
  这属于网关/模型侧抖动，**不能记作本次改动的收益**。
