- **P1-3 是唯一「已经在造成静默错误」的项**。`upstream[d][:4000]` 不报错、不留标记，
  下游 agent 拿到的是**看起来完整的截断文本** ⇒ 它会基于缺失内容下结论，且**事后无法复盘**
  （任务表里不留「被截断到多少」）。其余七项是**能力缺失**（做不到），P1-3 是**做错了且不自知**。

## 3. P1-3 施工设计

### 3.1 目标

上游产物注入下游 prompt 时，**不再静默整体截断**：截断必须留下「被截了多少 / 原文多长」的**可断言标记**，
且**保留头尾**（结论通常在尾部，整体砍尾丢的正是结论）。

### 3.2 四段式（对齐手册 A7/B11 的「交接上下文四段」）

```
【任务 {id} 的结果】（原始 {total} 字符）
{head}
…（中间省略 {omitted} 字符，保留头 {head_chars} + 尾 {tail_chars}）…
{tail}
```

- `head_chars` / `tail_chars` 由常量给，**合计 ≤ 原 UPSTREAM_TRIM**（预算不放大）。
- 原文 ≤ 预算 ⇒ **原样透传，一个字节都不加**（短路径不得被新格式污染——这是最容易写坏的地方）。
- 省略标记必须含**原始总长**与**省略量**，否则下游仍无法判断严重程度。

### 3.3 可写路径（限 worktree `agenthub-wt-4f8f5ce8`）

- **Modify**：`src/tasks.py`（新增 `format_upstream()` 纯函数 + `_run_task` 调用点）
- **Create**：`tests/test_task_handoff_l0.py`
- **不动**：`db.py` schema、任何端点契约、前端、生产服务

### 3.4 验收（每条都要红向自证）

1. 短文本（≤ 预算）⇒ **逐字节等于原文**，无任何标记（负向：加了标记就红）。
2. 超长文本 ⇒ 输出含原始长度、省略量、头尾标记；**总长 ≤ 预算 + 固定标记开销**。
3. **恰好等于预算** ⇒ 走透传分支（边界不多砍一刀）。
4. 尾部内容**必须出现在输出里**（这是「保留结论」的核心判据，负向：退回 `[:TRIM]` 就红）。
5. L0 全量零跳过 + `scripts/prepush.sh` 六步全绿。

### 3.5 排序（其余七项各自独立立项）

`P1-3` → （授权后）`P1-8` → `P1-4` → `P1-6` → `P1-7` → `P1-1` → `P1-2` → `P1-5`
