# CLI Apps（应用功能模块）· 接入说明（2026-11-25）

## 一句话

把 nanobot 的应用管理模块（`nanobot/apps`，MIT，0.4.2）**逐字节**搬进 hub，
配一层适配，让它出现在 hub 的「应用」页，并让**所有 agent**都能调用其中的资源。

## 四层结构

| 层 | 文件 | 性质 |
|---|---|---|
| 上游副本 | `src/vendor/cli_apps/nanobot/**` | **字节级**（md5 由 `tests/test_cliapps_l0.py` 钉住） |
| 依赖替身 | `src/vendor/cli_apps/{loguru,httpx}.py`、`nanobot/agent/plugins.py` | 适配（理由逐条见 `MANIFEST.md`） |
| 适配层 | `src/cliapps.py` | workspace/data 注入、技能软链桥、阻塞隔离、显式失败 |
| 门面 | `src/api_apps.py`（REST）+ `src/hubmcp.py`（MCP 三工具）+ `scripts/hub-apps.sh`（shell） | 薄 |

前端：`static/hub/17-apps.js` + `templates/index.html` 的 `#page-apps` + 系统菜单项「应用」。

## 「所有 agent 都能调用」是怎么做到的

三条路，任一可用即可，都打同一组端点：

1. **技能自动发现**（覆盖面最大）：装应用时生成 SKILL.md 并软链进
   `技术文档/skills/cli-app-<名>`。hub 的技能白名单里 `techdocs` 就指这个目录
   ⇒ `hub_skill_auto` / 各 agent 的 `UserPromptSubmit` 注入钩子会把它带进上下文。
2. **MCP**：`hub_apps_list` / `hub_apps_run`（默认可注册）；`hub_apps_install` /
   `hub_apps_uninstall` 在 `HUB_MCP_ALLOW_WRITE=1` 时才注册（装包改全机环境）。
3. **Shell 兜底**：`bash agenthub/scripts/hub-apps.sh …`（pi/codex/grok/jcode/opencode 都能用）。

## 行为差异（相对上游默认）

| 项 | 上游默认 | hub |
|---|---|---|
| workspace | `~/.nanobot/workspace` | `/fs/1000/ftp/技术文档`（技能才进白名单） |
| 状态目录 | `~/.nanobot/cli-apps` | `agenthub/data/cli-apps` |
| 技能可见性 | 只写 `plugins/` | 追加软链到 `skills/` |
| `run()` 工作目录 | 不限制 | `restrict_to_workspace=True` |

## 验收（2026-11-25 实测）

- `pytest tests/test_cliapps_l0.py` → **7 passed**（字节级 md5 闸 / import / 路由与 scope / 假装全链）
- 真实注册表拉取：103 个应用（CLI-Anything harness 79 + extension + public 24）
- `GET /api/apps/health` → `ok=true`，`protocol_schema=agent-app.v1`
- 生产装包未执行：本机没有「入口已在 PATH」的候选应用，真装一个等于往生产机装全局 npm/pip 包，
  留给用户在页面上点（每个动作都弹确认）。**这是刻意的边界，不是遗漏。**

## 已知边界

1. 前端是 hub 原生 JS 重画（上游那页是 React 编译产物，无法字节级搬进 hub 的单文件 `hub.js`）。
   ⇒ 上游新增的界面交互不会自动出现在 hub 页上，需要跟着改 `17-apps.js`。
2. `nanobot/agent/plugins.py` 是替身：上游的「启用指纹」只有 nanobot 自己的 loader 读，
   hub 用 `src/skill.py` 的技能路由，不消费它。上游若在 install 路径新增调用，本替身要补。
3. PyYAML 是**新依赖**（MIT，6.0.4）。没有它仍能装能跑，只是应用技能退化成 fallback 模板，
   `/api/apps/health` 会明示 `yaml=false`。
4. 卸载语义照抄上游：若 entry_point 仍在 PATH（例如工具是别处装的），上游会**保留安装态**
   并回 `removed=false`——那是正确行为，不要读成卸载失败。

## 回滚

```bash
cd /fs/1000/ftp/技术文档/agenthub
git revert <本次提交>
bash scripts/hub-restart.sh --reason "回滚 CLI Apps"
# 彻底清状态（可选）：rm -rf data/cli-apps
```
